## Network boundary

On Linux, the worker installs a seccomp filter after process creation and
before invoking the Core. The filter:

- validates the Linux audit architecture;
- denies `socket`, `socketpair`, connect/bind/listen/accept, send/receive,
  socket-option, shutdown, and batched message syscalls;
- denies x32 variants on x86-64;
- permits pipe-based parent IPC only;
- fails startup on an unsupported Linux architecture.

The test probe explicitly checks TCP, UDP, and Unix-socket creation.
`subprocess.Popen` closes inherited descriptors by default, and the seccomp
filter is inherited by any descendant.

## Startup and release binding

Readiness has no optional canary path. It remains false unless:

1. the historical frozen Core fingerprint reproduces;
2. repository commit evidence, when available, matches the frozen commit;
3. every Runtime release-manifest file matches its recorded length and hash;
4. the canonical release ID verifies;
5. service credentials exist;
6. two isolated canary executions are byte-identical and complete.

Deployment variables configure service operation only. They cannot define
release identity.

## Fingerprint coverage rationale

Included:

- every Python file under `src/orion`, as a conservative superset of the
  invoked frozen Core;
- every Python file under `src/orion_runtime`;
- frozen architecture contracts and operator declarations;
- Runtime contracts;
- `VERSION`, `workspace.yaml`, the verified corpus, and package metadata;
- Docker build inputs and Linux/reverse-proxy deployment definitions.

Excluded:

- tests, proof runners, and reports, because they verify but do not execute the
  Runtime;
- roadmaps, reviews, historical documents, examples, and publications,
  because they do not affect Runtime behavior;
- caches, generated bytecode, build output, and Git metadata;
- the release manifest itself, to avoid recursive identity; its canonical
  `release_id` and the immutable deployment-image digest bind it;
- the manifest generator, which is release tooling rather than deployed
  execution state.

## Manifest reference verification

The Gateway first verifies each artifact independently using the frozen native
parser and serializer. It then verifies the complete required reference graph:

- references are present;
- every target is the exact SHA-256 reference of the required earlier entry;
- no required reference can point forward, disappear, or be substituted;
- artifact ordering, uniqueness, terminal reference, and terminal
  certification remain independently enforced.

This is contractual reference validation only. It introduces no semantic
interpretation or repair.

## Operational boundary

The Runtime now enforces:

- one 30-second request clock beginning at connection setup;
- a worker timeout bounded by the remaining request time;
- CPU soft-limit signaling mapped to `504 core_timeout`;
- process-group SIGTERM followed by SIGKILL;
- aggregate worker temporary-directory observation plus file-size limits;
- tracking and termination of all active workers during shutdown;
- no result publication once shutdown starts;
- deterministic profile rejection immediately after representation and final
  relation-set construction;
- deterministic cleanup of worker pipes and temporary directories.

## Unresolved evidence

Finding 7 remains open because the supported Linux deployment verification was
not executed. Findings 1 and 6 also require their final Linux evidence through
that same gate. This is an evidence blocker, not authorization to weaken the
contracts.
