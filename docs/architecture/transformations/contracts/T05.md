## Transformation

- **Purpose:** connect a documented periodic input to explicit Scarabaeus state fields as driver, clock, measurement, or parallel view.
- **Conceptual operator:** Phase-3B placeholder `x_(t+1)=F(x_t,p,T(t))`; coupling `F` and the input role are `unknown`.
- **Required parameters:** input role, target field IDs, coupling identifier/strength/units, timestep/integration convention, shared epoch, phase origin/direction, merge role.
- **Optional parameters:** beat field, phase-lock threshold, uncertainty propagation, documented component filters.
- **Expected output:** provenance-bound periodic Engine contribution with separate component lineage or declared aggregation.
- **Known limitations:** input role, update function, state schema, and coupling are absent; causal interpretation is not authorized.

## Preserved Invariants

- **Identity:** cycle-source and Engine contribution identity.
- **Provenance:** both periodic sources, temporal profile, coupling declaration, and merge role.
- **Orientation Object ID:** unchanged and equal to the T04 merge input.
- **Source references:** lunar and solar component references retained separately unless aggregation is declared.
- **Epoch:** required and preserved.
- **Known constants:** only supplied periods, timestep, and conversion constants; none are registered by Phase 3C.

## Lossiness

- **Information preserved:** phase, periodicity, direction, epoch, component identity, and declared forcing value.
- **Information hidden:** complete input curve when the output references only a current forcing value.
- **Information aggregated:** lunar/solar components when the coupling uses their sum or a filtered value.
- **Information discarded:** intermediate states under a declared discrete integration profile.
- **Unknown:** field-level lossiness and reversibility while `F` and the input role remain unknown.

## Evidence

- **Current evidence level:** `E0`; the Tide System's role in Scarabaeus is undocumented.
- **Missing evidence:** input role, state/update schema, coupling operator, units, timestep, merge behavior.
- **Required datasets:** versioned synchronized phase/state fixtures with separate source components, epoch, units, expected state-field contribution, and T04 merge references.
- **Open questions:** Is the input a cause, clock, measurement, or parallel representation? Are components retained separately?

## Validation

- **Input validation:** compatible epoch/time basis/units, complete component IDs, ordered samples, representation version, provenance.
- **Output validation:** known state fields, coupling profile, timestep, units, epoch, merge role, source-component trace-back.
- **Invariant checks:** Orientation Object ID, phase, periodicity, direction, epoch, source references, and T04 merge compatibility.
- **Failure conditions:** unknown input role or `F`, incompatible time basis, undeclared aggregation, hidden coupling defaults, collapsed provenance, or incompatible merge identity.
