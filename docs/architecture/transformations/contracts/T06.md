## Transformation

- **Purpose:** reveal topological continuity, boundary pairing, twist, and side transition for a selected Engine path.
- **Conceptual operator:** Möbius quotient `(u,0)~(L-u,1)` from Phase 3B; mapping from Engine state to `(u,v)` is `unknown`.
- **Required parameters:** state/path-to-strip mapping, boundary pair, seam, traversal direction, landmark crosswalk.
- **Optional parameters:** display-only embedding, visual scale, sampling density.
- **Expected output:** quotient representation retaining path order, local neighborhood, seam, and state references.
- **Known limitations:** no Engine state profile or strip mapping is documented; global handedness cannot be preserved on the Möbius target.

## Preserved Invariants

- **Identity:** selected Engine state/path identity.
- **Provenance:** source path, mapping, seam, boundary rule, and contract version.
- **Orientation Object ID:** unchanged.
- **Source references:** state and landmark IDs retained.
- **Epoch:** retained by reference when present; not derived.
- **Known constants:** strip length or mapping constants only when explicitly supplied; currently none registered.

## Lossiness

- **Information preserved:** path order, continuity, local neighborhood, selected landmarks, and source trace-back.
- **Information hidden:** absolute time, speed, and state variables omitted from the strip profile.
- **Information aggregated:** states mapped to the same quotient point under a documented mapping.
- **Information discarded:** global handedness through the Möbius quotient; omitted state fields from the target view.
- **Unknown:** additional loss introduced by the undocumented Engine-to-strip mapping.

## Evidence

- **Current evidence level:** `E0–E1`; Möbius topology is named, but its relationship to Engine state is not documented.
- **Missing evidence:** Scarabaeus state schema, state-to-strip crosswalk, seam semantics, boundary pairs, landmark mapping.
- **Required datasets:** versioned ordered state-path fixtures with expected strip coordinates, seam crossings, boundary pairs, and landmark references.
- **Open questions:** Which state variables define `u` and `v`? Is the twist structural or visualization-only?

## Validation

- **Input validation:** valid state/path identity and version, ordered path, field units, provenance, and mapping availability.
- **Output validation:** valid strip coordinates, explicit seam/pairing, deterministic landmark references, and display/semantic separation.
- **Invariant checks:** Orientation Object ID, path order, local neighborhood, provenance, and declared handedness loss.
- **Failure conditions:** absent mapping, incomplete boundary pairing, hidden seam, inferred coordinates, false global orientation, or execution before operator documentation.
