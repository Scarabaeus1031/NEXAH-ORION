## Transformation

- **Purpose:** present time-bound observations as separate periodic lunar and solar components and their declared superposition.
- **Conceptual operator:** Phase-3B candidate `T(t)=A_L cos(ω_Lt+φ_L)+A_S cos(ω_St+φ_S)`; physical meaning and concrete parameters remain undocumented.
- **Required parameters:** amplitudes, periods/frequencies and units, phase origins/direction, epoch/time basis, sampling interval/window, output unit.
- **Optional parameters:** documented additional harmonics, component uncertainty, filter/window profile.
- **Expected output:** separate components and optional deterministic sum, all bound to the same epoch and sources.
- **Known limitations:** it is unknown whether the source describes physical tides, symbolic phases, or both; concrete units and parameter values are absent.

## Preserved Invariants

- **Identity:** observed subject and cycle-source identity.
- **Provenance:** Observation and both component sources.
- **Orientation Object ID:** unchanged.
- **Source references:** Observation, lunar component, and solar component references retained separately.
- **Epoch:** required and preserved.
- **Known constants:** only explicitly supplied periods/frequencies and unit conversions; none are registered by Phase 3C.

## Lossiness

- **Information preserved:** phase, periodicity, direction, epoch, component identity, units, and source trace-back.
- **Information hidden:** nonperiodic observation details and categorical correspondences.
- **Information aggregated:** lunar and solar components when a sum signal is produced.
- **Information discarded:** high-frequency or out-of-window content when the declared sampling profile removes it.
- **Unknown:** uncertainty, output unit, harmonic set, and meaning of `T` until evidenced.

## Evidence

- **Current evidence level:** `E0–E1`; a periodic view is present, but quantities and conventions are missing.
- **Missing evidence:** component definitions, physical/symbolic scope, epoch, units, parameter values, sampling profile.
- **Required datasets:** versioned time-series fixtures with separate component IDs, timestamps, phase origins, units, uncertainty, and expected declared superpositions.
- **Open questions:** What does Tide mean here? What unit does the output have? Which harmonics belong to the existing system?

## Validation

- **Input validation:** common time basis, compatible units, explicit component IDs, timestamp ordering, complete provenance.
- **Output validation:** separate component metadata, epoch, period/frequency, phase, sampling profile, and sum/component distinction.
- **Invariant checks:** Orientation Object ID, epoch, phase direction, periodicity, component references, and provenance.
- **Failure conditions:** incompatible epochs/units, missing component parameters, silent aggregation, undocumented harmonics, or attempt to treat the candidate as a verified operator.
