## Transformation

- **Purpose:** expose frequency, amplitude, phase, and residual descriptions supported by an ordered curve.
- **Conceptual operator:** Fourier analysis or least-squares fitting candidate from Phase 3B; no specific model is authorized.
- **Required parameters:** ordered samples/coordinates, transform or fit model, normalization, frequency range/aliasing assumptions, residual tolerance.
- **Optional parameters:** window, initial estimates, sample weighting.
- **Expected output:** model-bound estimates with residuals, ambiguities, and source-sample trace-back.
- **Known limitations:** parameterization may be absent, multiple fits may be valid, and the existing diagrams do not establish an operator.

## Preserved Invariants

- **Identity:** source trajectory identity.
- **Provenance:** curve samples, fit/transform profile, assumptions, residuals, and contract version.
- **Orientation Object ID:** unchanged.
- **Source references:** trajectory and sample references retained.
- **Epoch:** preserved when supplied; otherwise absolute phase remains `unknown`.
- **Known constants:** model, normalization, tolerance, and sampling constants only when explicit.

## Lossiness

- **Information preserved:** identifiable ratios and relative phase under the declared model and sampling profile.
- **Information hidden:** curve geometry when only fitted parameters are displayed.
- **Information aggregated:** ordered curve samples into estimated model parameters.
- **Information discarded:** geometric position and components outside the selected model if only estimates are retained.
- **Unknown:** uniqueness, aliasing, and recoverability until model and datasets are evidenced.

## Evidence

- **Current evidence level:** `E1`; analytical recovery is possible in principle but not documented as an existing operator.
- **Missing evidence:** canonical model, parameterization requirements, normalization, residual metric, aliasing and ambiguity policy.
- **Required datasets:** versioned ordered curve fixtures with units/parameter coordinates, expected candidate estimates, residuals, ambiguous cases, and declared round-trip fields.
- **Open questions:** Is parameter `t` retained? How are ambiguity, aliasing, and noisy curves represented?

## Validation

- **Input validation:** ordered samples, coordinate/parameter units, sample sufficiency, model/profile completeness, provenance.
- **Output validation:** estimates with units, residual and ambiguity status, model/version, source trace-back.
- **Invariant checks:** Orientation Object ID, identifiable ratios/relative phase, source references, provenance, declared round-trip scope.
- **Failure conditions:** missing parameterization/model, nonidentifiable result presented as unique, hidden fit assumptions, absent residual, or execution before candidate approval.
