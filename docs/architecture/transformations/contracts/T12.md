## Transformation

- **Purpose:** expose stable polyhedral regions, addresses, and adjacency for stellar directions.
- **Conceptual operator:** Phase-3B candidate face assignment by maximum face-normal dot product; within-face projection and unfolding are `unknown`.
- **Required parameters:** dodecahedron orientation, face normals/IDs, assignment rule, boundary tolerance/tie rule, within-face coordinates, adjacency table.
- **Optional parameters:** versioned unfolding layout, labels, visual padding/clipping.
- **Expected output:** each source point bound to a face/cell, local coordinate or declared absence, boundary status, and topology.
- **Known limitations:** authoritative orientation, cell rule, landmark mapping, local projection, and unfolding are missing.

## Preserved Invariants

- **Identity:** stellar point identity.
- **Provenance:** source frame/epoch, polyhedron profile, assignment rule, face/local coordinate, and contract version.
- **Orientation Object ID:** unchanged.
- **Source references:** stellar point and source representation IDs retained.
- **Epoch:** preserved.
- **Known constants:** face normals, orientation, tolerances, and adjacency only when supplied by a versioned profile.

## Lossiness

- **Information preserved:** source direction by reference, point ID, face address, local coordinate when stored, and adjacency.
- **Information hidden:** continuous spherical coordinate and metric in a cell-focused view.
- **Information aggregated:** directions into common faces/cells.
- **Information discarded:** exact direction when only a face/cell ID is retained; metric through planar unfolding.
- **Unknown:** distortion and reversibility until within-face projection and unfolding are documented.

## Evidence

- **Current evidence level:** `E0–E1`; dodecahedral addressing appears, but orientation and assignment are not evidenced.
- **Missing evidence:** polyhedron orientation, face/vertex choice, normals, tie rules, within-face coordinates, adjacency, landmark crosswalk, unfolding.
- **Required datasets:** versioned spherical-point fixtures with frame/epoch, expected face/local coordinates, face-boundary and vertex cases, adjacency, and source landmark IDs.
- **Open questions:** Are faces, vertices, or dual cells authoritative? How are boundary points handled?

## Validation

- **Input validation:** point identity/version, valid spherical frame/units/epoch, finite coordinates, provenance.
- **Output validation:** valid profile/version, face ID, local coordinate status, deterministic boundary tie, symmetric adjacency, source trace-back.
- **Invariant checks:** Orientation Object ID, point references, epoch, face adjacency, provenance, declared quantization.
- **Failure conditions:** missing orientation/profile, unresolved boundary tie, invalid face/adjacency, inferred landmarks, hidden unfolding, or execution before candidate approval.
